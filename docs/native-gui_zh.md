# 原生 GUI 评估

inout 的应用方向是 Rust 原生绘制的 GUI，Next.js 当前构建通过 HTTP 访问的浏览器文件管理器；[技术路线](../ROADMAP.md#technology-direction)计划保留 React 组件，迁移到 Vite 构建。目前已经有可独立构建、控制真实文件服务的 Slint 桌面试验版，不嵌入 WebView。现有 Tauri 桌面和 Android 安装包仍属于过渡预览，Slint 试验尚未替换这些发布产物。

按照用户选择，当前验证顺序是 **先试 Slint，无法满足要求时再切换到 egui/eframe**；Iced 保留为单独评估的桌面方向备选。正式采用前仍需通过各目标平台的实际检查。控制器和会话所有权已经独立于渲染器，切换 Rust GUI 可以复用同一服务和传输契约。

原生 GUI 可以独立设计布局、组件和动画。Next.js 管理器提供审美参考，应用的页面结构可以围绕分享任务及平台操作习惯重新组织。保留可配置的点阵品牌、易读的本地语言界面以及传输和二次确认契约；当前试验的配色与双栏布局属于已实现的选择，后续可以独立于浏览器管理器演进。

## 三个候选的适配情况

官方文档与发布源码核对日期为 2026-11-15。

| 候选 | 对 inout 的优势 | 正式采用前的关键检查 |
| --- | --- | --- |
| egui/eframe 0.37.0 | 直接用 Rust 组合界面，支持选择 Glow 或 wgpu；MIT OR Apache-2.0 许可；提供 Android 示例 | Android 需要 GameActivity 与明确的 AccessKit 接入。iOS 需要单独构建 winit/Metal 宿主。中文字体、输入法、控件无障碍及每种架构仍需实测。 |
| Slint 1.18.1 | 声明式布局与动画，稳定的 1.x API，具有 Android/iOS 接入文档 | Android 最低 API26，高于当前 API24 目标，发布版 Android 后端使用 Skia。Android 无障碍接入与桌面/iOS 不同；还需明确 GPL、无版税或商业许可及各商店的分发方案。 |
| Iced 0.14.0 | Rust 消息、更新和视图结构，桌面可选择 tiny-skia 软件渲染器 | 项目仍声明为实验性软件，原生无障碍工作尚未完成；本次核对的版本没有同等完整的 Android/iOS 应用接入路线。本次未测量 Iced 性能。 |

三者都可以直接绘制界面而不依赖 WebView。自绘界面仍需要字体、布局、图形驱动和平台接入；它也不自动等同于系统原生控件或更低的资源开销。egui 与 Iced 可按事件请求重绘，空闲测试应保留正常的事件驱动行为。Slint 的移动端 Skia 路径与本次桌面 FemtoVG 路径分别验收。

Slint 的 Android 后端实现了 InputConnection 和输入组合状态处理，不能把它描述为只支持 ASCII。实际中文输入、Back、软键盘与安全区域仍需设备检查。egui 的默认字体不能单独满足中文文件名覆盖，禁用默认特性时应明确保留系统字体回退或提供已声明的替代方案。

许可会影响分发路线。egui 的宽松许可较符合当前目标；Slint 的无版税应用许可并不等同于不受限制的 FLOSS 库许可。F-Droid 路线需要完整开源依赖及源码构建，Slint 自身的相关示例使用 GPL 分发并从源码构建 Skia。Apple 等渠道的许可、签名和商店要求也需分别确认，现有项目许可及安装身份不能被静默改变。完整发布源码和官方许可链接见[英文评估](native-gui.md#official-references)。

## Slint 桌面功能试验

[apps/native-slint](../apps/native-slint/README.md) 独立于核心的默认构建，锁定 Slint/slint-build 1.18.1、winit、FemtoVG 优先和桌面无障碍适配。Windows 另启用软件渲染后备，在 OpenGL 初始化失败时使用；Linux/macOS 渲染特性不变。已经接入系统文件夹选择、可选的掩码口令、公开上传/管理选项、局域网或回环绑定以及实际端口。可以选择、复制实际地址并交给系统浏览器打开；浏览器启动失败时保留当前语言的恢复提示，允许复制地址手动访问。名称和编译生成的 5×7 点阵字来自产品配置，安装和签名身份保持独立。

简中、繁中、英语使用本地类型化词条；四种主题调整已经设计的界面表面。语言和主题切换保留设置草稿、监听及已接纳传输。启动退出由真实控制器准备状态推进；启动前设置 `INOUT_NATIVE_REDUCE_MOTION=1` 可关闭动态效果。偏好暂不持久化，系统减少动态效果偏好的自动识别仍待实现。

运行期间停止或关闭应用先请求二次确认，取消后保持原监听及传输体。确认停止后清理拥有的服务，保留有界的本轮传输收据；下一次成功启动才重置记录。下载已发送字节不能证明另一台设备已保存。持久历史、断点续传、单任务取消、安全打开文件、二维码/网络推荐及原生实时设置/诊断编辑器仍有独立任务。

本地优化 Linux 版通过了移出源码目录后运行的真实上传/下载校验、公开删除拒绝、暂停上传期间语言/主题与取消停止保持、停止后的收据保留、键盘确认和关于窗口行为检查。原生测试有 14 项，独立 HTTP 浏览器管理器有 131 项 Chromium 用例通过。这些结果不代表移动端、安装升级或辅助设备已经验收。

锁定的 AccessKit AT-SPI 适配缺少 EditableText，并把禁用按钮报告为可用。直接响应式控件状态和应用动作保护可以阻止物理及强制语义后台激活，但无障碍状态报告错误仍是正式采用前的关卡。完整读屏、中文输入组合和各平台动态效果偏好需单独验证。

当前本地 Linux 功能试验的可执行文件为 18,752,320 字节（17.88 MiB），包含精确的 36 文件 / 1,084,605 字节浏览器导出及许可说明的 ZIP 为 9,216,822 字节（8.79 MiB）。运行依赖目标系统图形、字体、显示及桌面服务，不捆绑这些系统库，也不需要运行时 Node/Python/WebView。这些体积与下方一次性对照程序分别记录。项目源码继续使用 MIT；Slint 无版税2.0条款允许带署名的一般用途桌面及移动应用，另见[第三方说明](../apps/native-slint/THIRD_PARTY.md)。F-Droid 自由源码与渠道许可选择、Apple 分发要求及实际移动端接入仍是独立关卡。

## Windows 默认渲染器与输入

Windows 源码在 FemtoVG 无法初始化 OpenGL2 驱动时，使用 Slint 既有的软件渲染后备。锁定版本的 Fluent ComboBox 提供可读值，却未处理写值动作；语言和主题控件现验证启用状态及当前模型值，再使用既有语言回调或主题索引绑定。保留标准鼠标/键盘回调，呈现变化不重建服务所有者。

x86/x64 源码构建各通过14项原生测试、严格Clippy和锁定Rust/MSVC优化编译。标准用户的 Windows10x64 实际检查通过默认渲染启动、简繁英选择值与本地化标签、主题保留、无效/禁用写值拒绝及闲置正常关闭。x86 在64位系统运行，尚不代表真正32位系统已通过。

功能测试保留上一轮CI的精确浏览器资源并使用各自的新程序。两个原生宿主均使用中文目录和实际回环端口，通过文件下载、网页200、匿名创建目录201及公开删除403/文件保留。每个原2MiB上传在语言/主题变化和取消停止、正常关闭期间保持同一连接，随后完成201，磁盘/再次下载长度与SHA-256一致。确认停止和正常关闭后，监听及未发布暂存文件均清空。

[Windows源码构建体积](distribution/size-and-runtime.md#windows-source-build-with-software-fallback)与当前及历史CI包分开记录。[d42048d 的 CI](https://github.com/zocs/inout-next/actions/runs/44239092778)还对两份包内精确程序执行公开的启动、语言/主题及正常关闭回归，该探测不启动分享。上方源码构建功能验证依据原生无障碍和真实服务/文件证据；标准下拉选项选择、滚动及视口外收据、输入法/读屏、安装/离线包、真正32位Windows、显示帧、输入延迟和能耗仍需独立验证。

锁定的 Slint Android 使用 native-activity/Skia，最低API26；平台助手转发输入组合和Back。这些源码事实不代表本应用的移动输入、TalkBack、arm64/16KiB或生命周期已验收。持久Service、SAF及iOS宿主仍需独立适配。本轮桌面工作没有构建或发布Slint APK，现有Tauri预览的API24及签名身份不变。

## 已完成的 Linux 初步测量

两个独立验证程序使用同一真实 Rust HTTP/存储核心、两个 Tokio 工作线程、有界消息、包含简繁中文的一万条文件名，以及相同的优化 Release 配置。环境是 Linux x86_64、X11/XWayland 和 Mesa Intel 图形驱动。字体使用系统回退，实际字体、布局与列表模型尚未控制为完全相同。这些程序用于评估，尚未成为应用预览。

| 指标 | egui 0.37 / Glow | Slint 1.18.1 / FemtoVG |
| --- | ---: | ---: |
| 温启动至已填充列表的渲染标记，中位数 | 125.96 ms | 181.08 ms |
| 同一标记的 p95，每个候选 15 次 | 167.71 ms | 207.35 ms |
| 去除调试符号后的可执行文件 | 12.01 MiB | 16.84 MiB |
| 单可执行文件 ZIP | 5.01 MiB | 7.85 MiB |
| 短时空闲进程 PSS，中位数 | 46.32 MiB | 48.09 MiB |
| 短时空闲私有内存，中位数 | 36.69 MiB | 38.01 MiB |

渲染标记要求服务地址及完整文件名模型已准备好，但发生在**系统实际显示和 GPU 完成之前**。温启动没有清除系统、驱动和字体文件缓存。每组只有 15 个启动样本，因此这里的最近秩 p95 正好是最大样本，尚不能视为稳定的尾延迟估计。

共完成 30 次交替启动和六次 12 秒工作负载。每次都传输 64 MiB 文件，核对长度与 SHA-256，最终后端记录没有活跃传输。客户端读取经过刻意限速，这证明 UI 工作期间的传输完整性，尚未测量局域网最大吞吐。两者都实际滚动超过列表范围的 70%，但重绘节奏和界面工作不同，不能按本次活跃 CPU 或回调时间排列帧效率。已报告的动画内存/CPU 采样区间发生在传输结束之后。

空闲内存来自每个候选三次短时运行。选定空闲区间内，在 10 ms 的 CPU 计时精度下没有检测到计时增加，持续空闲耗电仍需测量。PSS 按共享页面分摊进程内存，但不包含完整 GPU 分配；文件与 ZIP 大小不包含静态 Next 资源、外部系统库和字体、分发声明及已安装运行时。当前 Tauri 与 FileInfra 的分发包测量另见[体积与运行报告](distribution/size-and-runtime.md)。

## 核心与界面的运行边界

原生 UI 事件循环负责控件和绘制。`share-host` 拥有独立于渲染器的控制器及 `HostSession`，管理脱敏状态、二次确认、有界收据和清理；Tauri 重导出既有控制器契约。Slint 通过双工作线程 Tokio 桥及最多 16 条排队命令组合会话，网络和异步存储不阻塞 UI。传输接纳/终结发出状态通知，逐数据块进度仍只更新原子计数。活跃或脏状态按 250 ms 采样，空闲等待；至多排队一次的最新状态投递合并进度。FIFO 命令编号和持续保留的完成水位，避免被动采样提前释放已接纳动作的忙碌和焦点所有权。

系统文件选择器、存储授权和生命周期适配独立于渲染器。切换语言或主题、隐藏面板以及重建窗口表面不得隐式取消已经接纳的传输。主动 Stop、关闭或取消需要预期的二次确认；系统终止、崩溃和恢复具有独立协议。Android Service 与 SAF、iOS 前台及有限后台运行仍是平台任务，选定 GUI 框架并不会自动完成这些工作。

名称来自 `product.json`，安装和签名身份保留在 `config/native-identity.json`。Slint 试验已经实现点阵像素字 LOGO、按真实准备状态推进的启动退出和明确的减少动态效果配置。现有 CSS 动画、Slint 渲染回调或 Tauri 构建检查不能替代实际显示帧和升级兼容性验收。

如果出现无法解决的必要平台故障、关键输入/无障碍/分发要求无法满足，或统一工作负载下的持续测量证明资源成本不可接受，再切换到 egui。尚未测试的平台保留为验证任务，不直接视为 Slint 失败。

## 正式选型的性能与平台验收

1. **先证明高风险平台。** 用拟发布的渲染器构建 Windows i686，并在真正的 32 位 Windows 上运行。Android 分别检查最低与当前系统、arm64、16 KiB 实际运行、中文输入组合、Back、安全区域和 TalkBack。iOS 检查宿主、场景、输入、VoiceOver 与授权文档访问。交叉编译与设备运行分别记录。
2. **统一字体及界面工作。** 对照实验使用相同授权字体、窗口尺寸、DPI、可见行数、滚动距离、动画时长和进度刷新频率，另测生产环境的系统字体回退。语料覆盖英文、简繁中文、长文件名、罕见字和混合文字，包含冷字体发现、首次中文字形与温缓存阶段，检查离线覆盖、区域字形、选择、剪贴板和密码输入。
3. **测量实际显示与输入延迟。** 进行多次冷/温启动、至少 60 秒滚动、调整窗口及输入工作负载，并单独测量持续空闲。记录样本数量、中位数、尾延迟及实际显示的延迟帧。60 Hz 的建议帧预算为 16.7 ms，120 Hz 为 8.3 ms；这些预算尚不是已达成的结果。
4. **使用平台追踪验证边界。** Linux 使用进程与合成器分析；Windows 使用 ETW/WPA，以及渲染器支持时的 PresentMon；Android 使用 Perfetto/FrameTimeline、simpleperf 与内存检查；Apple 使用 Instruments/Metal 追踪。先确认工具真正观测到候选渲染器。Rust 回调计时测 CPU 工作，GPU 查询测支持的 GPU 执行阶段，分别标注其含义。
5. **分开记录资源与传输成本。** 记录压缩包和安装体积、核心/UI/网页/字体资源、外部运行时、进程私有/PSS 内存、GPU 和字形缓存、空闲重绘、CPU 与持续能耗。传输测试统一文件、磁盘、冷热缓存和完整校验，在实际局域网及慢客户端上对照 1/4/8 个连接的吞吐、CPU 和峰值内存。虚拟机用于排查兼容性及功能问题，硬件上的帧、能耗和网络结果单独记录。
6. **检查服务所有权与分发。** 权限变更、窗口销毁重建和前后台切换遵守服务契约，确认后的停止清理应用拥有的工作。检查移动/离线运行的分发包、许可和源码构建、身份、签名及各商店要求，再发布替换应用。

完整官方发布版本、输入和字体实现、平台适配及许可参考见[英文评估](native-gui.md)。
