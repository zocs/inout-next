## Runtime and packaging

The application targets a Rust-rendered GUI; Next.js remains its HTTP/browser manager. Existing Tauri artifacts and target evidence are transitional. [Native GUI evaluation](native-gui.md) records both the exploratory egui/Glow versus Slint/FemtoVG comparison and the functional Slint Linux desktop trial. The selected order is Slint first, with egui as the fallback. The extracted `share-host` controller/session has no renderer dependency. Slint runs the same real HTTP service through a bounded Tokio bridge, with native folder/address/clipboard/browser controls, three languages, four themes, current-run receipts and confirmed Stop/close.

Current native setup offers existing common directories and leading-`~` expansion, three access presets (manage includes upload) and distinct startup errors. Addresses are conservatively labelled, ordered and selectable; the LAN QR contains only the URL. Preferences/drafts are atomically saved per user without the key. Browser previews use an inline allow-list, bounded text and explicit large-image loading. Linux/Android filesystem-resource checks cover bind mounts and reject uncertain cross-device layered origins. Valid `nsfs` namespace-handle mounts outside both subtrees preserve the proof; opaque mounts within either subtree are rejected. Unavailable topology and other platforms retain the bounded identity scan.

Windows source keeps FemtoVG preferred and enables a software fallback when OpenGL initialization fails. Native language/theme value actions validate enabled state and current model membership. Both architectures pass the [local Windows source checks](native-gui.md#windows-default-renderer-and-input), including the same original2MiB body through presentation changes/canceled interruption and exact final file hashes. These functional fixtures reuse the historical CI's browser resources with new executables. The packages at d42048d include those fixes and pass the public startup/choices/normal-close probe against their exact binary bytes without starting sharing. Linux/macOS renderer features are unchanged. Next.js remains the current browser export tool; [Vite + React](../ROADMAP.md#technology-direction) is queued.

Local native/relocated-package verification is separate from target compilation and release. API24, selected-renderer i686 execution on a real 32-bit OS, CJK/IME/accessibility, mobile lifecycle, installed/offline packages and store results require independent verification. The locked AT-SPI bridge's missing EditableText and incorrect disabled-button metadata remain assistive adoption gates, despite verified application action guards. Slint Android's API26/Skia route is unvalidated and does not change the existing preview's API24 minimum.

Pinned Slint Android uses native-activity and has source-level IME/Back forwarding. Its royalty-free2.0 terms permit general-purpose mobile apps with attribution; this does not establish app/device input, TalkBack, Service/SAF, arm64/16KiB, F-Droid source/channel selection or store acceptance. No Slint APK is produced by current CI.

CLI ZIPs contain the compiled server, static `web/`, product metadata, licence and usage instructions. They do not require Node or Python. Transitional Tauri native packages additionally require a platform webview: WebKitGTK4.1/GTK3 on Linux and WebView2 on Windows. Current Windows NSIS uses a downloadable WebView2 bootstrapper; it is not verified offline GUI distribution. New Slint GUI release builds require and embed the validated browser export; native ZIPs contain the executable, product/usage and source/framework/qrcodegen/tempfile notices without duplicate `web/`. Historical trial archives retain their separate web resources. Slint's Linux runtime uses OS display/graphics/font/desktop services and an external browser, without WebView or a bundled system-library closure. See [package size and runtime](distribution/size-and-runtime.md).

The Ubuntu22.04 Tauri native executables import GLIBC through2.34. This rules out a glibc2.27 claim for those executables and does not audit the minimum versions of every bundled/system dependency. The current CI Slint executable at d42048d directly imports GLIBC through2.35; the separately built local Slint executable imports through2.43. Neither archive size, direct-symbol ceiling nor successful extraction establishes the complete dependency floor or old-distribution compatibility.

Tauri's [Windows installer guide](https://v2.tauri.app/distribute/windows-installer/#building-for-32-bit-or-arm) supports32bit `i686-pc-windows-msvc`. Executing that binary on Windowsx64 is distinct from testing a32bit Windows OS. Linux32bit is not a declared target. Modern browser/System WebView requirements remain relevant to the static Next export.

Windows upload/copy publication requires a filesystem supporting hard links; file/directory move and rename are disabled. Linux/Android/Apple publication and moves require native exclusive rename support. Directory copying is unsupported. The Android preview uses the existing filesystem provider inside app-private storage. Future SAF URIs require a separate adapter with truthful provider capabilities.

Android shares `files/shared`, separate from packaged runtime resources. Keep the app on screen: Home/root Back stops the listener, cancels unfinished transfers and leaves sharing stopped on return. Configuration recreation and true Activity destruction also leave sharing stopped; saved files survive, while clearing application data or uninstalling removes them. Another device's browser manages the share. This preview has no foreground Service or arbitrary-folder/local-manager capability.
