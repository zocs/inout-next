# Privacy Data Inventory

Checked: 2026-11-16. Scope: [desktop preview.1](preview.md), [Android foreground preview.2](android-preview.md), unreleased language/theme preferences, process-local transfer observations, Tauri diagnostics, the opt-in Slint desktop trial and configurable inout branding. The Rust GUI keeps Next.js for HTTP browsers; current released Tauri packages remain transitional. This is preparation for channel-specific disclosures, **not a published privacy policy, completed store form or exhaustive third-party privacy audit**. See [store readiness](store-readiness.md) and [official sources](store-sources.json).

## Current First-Party Data Paths

Unreleased browser source stores only validated language/theme choices in product-independent localStorage keys; storage denial leaves session preferences usable. Slint locale/theme and setup drafts remain process-local and are not saved to browser storage. The Rust transfer control keeps relative file paths, IDs, kinds, sizes/counts, policy revisions and times in memory, bounded to 1,024 active and 200 terminal records. It supplies no public HTTP history route or telemetry; records are not durable crash-recovery state. Slint observes active/dirty state at a bounded cadence and shows current-run receipts, retaining them after Stop and resetting them at the next successful Start. Durable native history, safe-open and live-setting/diagnostic editors remain pending; Tauri diagnostics still exist. Permission-only edits retain sessions, while key replacement invalidates old credentials for new admissions and leaves admitted work on its prior snapshot.

Android's current manifest uses `INTERNET` plus AndroidX's app-specific signature-protected internal receiver permission. It requests no all-files, media, location or foreground-service permission. Sharing runs only in the foreground; Home/root Back closes the listener and cancels incomplete requests, and return requires explicit Start. This permission/lifetime scope does not establish future SAF/provider/notification behavior or Android17 local-network permission handling. Fresh host-page/process creation resets in-memory access drafts; saved shared files persist independently.

The current first-party application implements no product account registration, ads, analytics service, purchase flow, push service or third-party cloud relay. This statement describes the implemented first-party features, not an assertion that every dependency, OS service, store, browser or file provider has been audited. Adding such a feature requires an explicit module/host boundary, updated disclosure and a freedom-preserving build when F-Droid is a target.

## Store Disclosure Interpretation

Google's [Data safety definition](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en) describes collection as transmitting data off a user's device, regardless of whether the destination is the developer or another server. Local-only processing is excluded; user-initiated expected transfers have specified **sharing** exceptions. A sharing exception is not automatically an exception from **collection**, and the current HTTP service cannot use the end-to-end-encryption exception. Map actual transmitted file/metadata categories and the completed app's behavior to the form before choosing answers.

Apple's [privacy-label definition](https://developer.apple.com/app-store/app-privacy-details/) asks whether off-device transmission lets the developer/third-party partners access data longer than needed to service a real-time request. A direct user-controlled peer transfer does not automatically mean the developer collects those bytes. Check the final native dependencies, logging, file providers and destinations against Apple's own definition; do not copy Google's answers or use the presence of a webview as an exemption for the application's own traffic.

All current LAN file/session/key traffic uses HTTP. Authentication controls access but does not encrypt the connection. No current evidence supports “all data encrypted in transit,” end-to-end encryption or a production-safe public-internet sharing claim. Before a store candidate, S4 must deliver appropriate transport security/pairing, truthful disclosure, access scope and revocation; the exact design needs its own implementation tests and reviewed origin policy.

## Materials to Complete Before Submission

- Publish a stable, publicly accessible privacy policy naming the app and actual publisher/contact mechanism; expose it from the native app as well as store metadata. Record data types, purposes, recipients, storage/retention, user sharing/deletion controls and security practices. Do not invent a publisher address/email or describe unimplemented mobile behavior.
- Inventory the final Rust, JavaScript, Kotlin/Java/Swift/native libraries and store-specific SDKs. Record permissions, endpoints and on/off-device behavior, including optional cloud SAF/document providers; a local core does not prove a cloud document provider is local.
- For Apple's applicable platforms, determine actual required-reason API calls and SDK manifest/signature obligations. Place each accurate `PrivacyInfo.xcprivacy` in its required bundle, inspect the built archive and aggregate the Xcode privacy report. Reason codes are chosen from real use, never filled from a generic template.
- Test denied/revoked directory and network grants, Stop, background/timeout cleanup and key/session invalidation on the target OS. User instructions and consent must describe what is actually shared and how to stop it.
- Keep OS/store/browser collection distinct from the publisher's application disclosures. Recheck the inventory for every major feature, SDK or distribution change and before each store candidate.

The detailed store gates S1–S7, account/testing conditions and source-build/signing work remain in [store readiness](store-readiness.md). The Android app-private foreground adapter and direct preview certificate exist; SAF/native foreground Service, iOS code, published policy, store forms, native privacy reports and store acceptance remain pending.
